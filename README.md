# 豆豆国的地铁 — 成都地铁 1 / 2 号线 SVG 线路图 + 3 车厢列车运行模拟

纯 vanilla 单页网页应用：用 SVG 绘制**成都地铁 1 号线与 2 号线**（按 OpenStreetMap 真实轨道几何与站点坐标），
站点轻点即弹出悬浮窗（到达时间 / 列车状态 / 派车按钮），一列 **3 节车厢**地铁沿线按站运行：
区间加速—巡航—制动进站—到站停车—开关门—发车—终点折返，支持 iPad 双指缩放/单指平移/双击缩放。

* **零外部依赖、零构建步骤**：没有 CDN、没有 web font、没有图标字体、没有 npm 包、没有模块打包。
  只有 5 个文件 + 内联/内嵌 SVG，直接 `file://` 打开或任意静态服务器托管都能跑。
  （`tools/build-data.py` 是**一次性数据生成脚本**，跑网页不需要它。）
* 目标设备：**iPad（触摸优先）**，同时兼容鼠标（滚轮缩放 + 拖动平移）。

### 在 iPad 上打开（本机是 WSL2）

`serve.sh` 会自动打印候选地址，步骤：

1. 在 WSL 里运行 `./serve.sh 8080`（已 `--bind 0.0.0.0`）。
2. 在 **Windows 管理员 PowerShell** 里把端口转发到 WSL（只需做一次；`<WSL_IP>` 用 `hostname -I` 查看，
   一般形如 `172.2x.x.x`）：

   ```powershell
   netsh interface portproxy add v4tov4 listenport=8080 listenaddress=0.0.0.0 `
     connectport=8080 connectaddress=<WSL_IP>
   netsh advfirewall firewall add rule name="potato-8080" dir=in action=allow protocol=TCP localport=8080
   ```

3. iPad 与电脑连同一 Wi-Fi，Safari 打开 `http://<Windows 局域网 IP>:8080/index.html`
   （Windows 上用 `ipconfig` 找 IPv4 地址，通常 `192.168.x.x`）。

注意事项：WSL2 的 IP 每次重启可能变化，变化后要
`netsh interface portproxy delete v4tov4 listenport=8080 listenaddress=0.0.0.0` 再重加；
若 portproxy 不通，可直接访问 `http://<WSL_IP>:8080/`（需 Windows 防火墙放行），
或把目录复制到 Windows 侧用 `python -m http.server 8080` 起服务。

## 2. 线路图（俯视地图，真实几何）

* **1 号线**（蓝 `#0d6cb5`）：北起**韦家碾**，向南经升仙湖、火车北站、天府广场、火车南站、世纪城等，
  在**四河**分叉——主线南至**科学城**，支线东折经**广都**至**五根松**。主线 33 站，含支线共 35 站。
* **2 号线**（橙 `#e8792a`）：西北起**犀浦**，经茶店子客运站、一品天下、中医大·省医院、人民公园、
  在天府广场与 1 号线换乘，再经春熙路、牛王庙、成都东客站，东南至**龙泉驿**，共 33 站
  （32 站在营 + 1 座在建）。
* 两条线路共用 **67 个站点**（天府广场是唯一换乘站，1/2 号线在此十字相交）。
* **走向不是手画的**：轨道几何取自 OpenStreetMap 的线路关系与轨道 way（1 号线韦家碾→四河 199 点 +

  1 号线南北贯穿、2 号线东西横穿、在市中心十字相交，四河以东是支线分叉。
* **车站样式**：普通站圆点（按所属线路着色）、**端点站实心**、换乘站双圆环、**在建/未开通站虚线空心**；

* **站名标签**：中文 + 英文 + 可换乘线路编号小牌；沿线左右交替摆放，并有**防重叠排布**
  （候选位依次为首选侧 → 反向侧 → 上下偏移 15/30 → 旋转 ±46°，按与已放置标签的重叠面积 + 压住其它站点圆点的罚分取最优解）。
  标签字号与偏移**屏幕恒定**，低缩放时只显示换乘站/端点站/分叉站（LOD）。
* **底图**：OSM 真实水系（锦江、府河、南河、沙河、清水河、江安河、东风渠、鹿溪河、摸底河）、
  湖泊多边形（兴隆湖、麓湖、升仙湖、北湖、青龙湖）与快速路骨架（motorway/trunk/primary），
  叠加细腻的城市街区纹理与网格。**底图为示意装饰，非导航用途。**
* **运行状态**：左上角 HUD 常驻显示 线路/方向、当前站、下一站、目标站、已运行里程、速度、预计到达、

## 3. 列车（每线一列，共 2 列 · 每列 8 车厢）与运行模拟

* **列车数量**：每条线路 1 列 —— 1 号线列车（韦家碾↔科学城/五根松）与 2 号线列车（犀浦↔龙泉驿），
  **打开网页即全部自动运行**（各自从始发站发车、区间加速、到站开门关门、终点折返）。
* **列车编组：每列 8 节车厢**（车长 9、间隙 1.2，整列 80.4 地图单位；端点站外的折返段留长 120 单位，
  保证整列车能完全停在轨道上）。
* **列车强调显示**（便于在图上找到车）：车身外一圈**白色光晕 + 线路色描边**（带缓慢呼吸动画，深浅底图上都醒目）；
  车头上方有一个**跟随标签贴片**（线路徽标 + 实时状态，如「1号线｜巡航 60km/h」「2号线｜开门中」），
  贴片可点（等同点列车切换控制对象）；当前控制的车额外有**加粗描边 + 车头虚线选中环**。
* **点击列车切换控制对象**：轻点地图上的列车，或面板顶部「列车」卡片（每列车一张，显示当前位置与状态），
  即可把“当前控制列车”换成它 —— 右侧面板的**线路/交路**、HUD、导航目标、跟随视图、暂停/复位均随之更新。
  当前控制的车有加粗描边与车头虚线选中环，另一列不隐藏、照常运行（只是提示不弹、只静默发车）。
* **下一站强调 + 到站气泡**：每列车前方**下一站在地图上有脉冲圆圈**（按所属线路配色）；站名上方悬浮
  **到站气泡**显示「线路徽标 + 还差 X 分 Y 秒」；若同一站同时是多列车的下一站，气泡**折叠为一条**
  「N 趟列车 · 最短时间」，点它展开成多条单独气泡（每条可点，点了就切到那列车）；
  **点地图空白处收起展开的气泡**。气泡会自动避开 HUD、自动重叠避让，并始终留在舞台内。
* 3 节车厢刚性连结：车长 14、间隙 1.8、半宽 5.0（地图单位，为可视性做了夸张）。车体由**路径弧长参数化**生成：
  以列车前端里程出发按 `fS = sHead − dir·i·(车长+间隙)`、`rS = fS − dir·车长` 求每节车厢首尾，
  再沿线路采样点用法向偏移曲线生成车身轮廓——因此转弯时整列车像蛇一样贴着线路弯曲，车头朝该点切线方向。
  车身涂装（顶部色带）按所属线路自动变色（1 号线蓝 / 2 号线橙）。车头端做了鼻锥收窄 + 深色风挡，
  两侧各 4 扇车窗、各 2 组车门。
* **动力学**（真实时间戳驱动：`requestAnimationFrame` + `performance.now()` 求 delta；单帧 delta 上限 0.12 s，
  大 delta 再拆成 ≤ 0.04 s 子步，切后台回来不跳变；多列车在同一循环里各自子步推进）：

  | 项 | 取值 | 说明 |
  |---|---|---|
  | 巡航速度 | 60 km/h | 线路设计最高 80 km/h；区间巡航取 60 |
  | 加速度 | 0.75 m/s² | 加速到巡航约 185 m |
  | 制动减速度 | 0.9 m/s² | 按 `v = √(2a·remain)` 收敛到 0，停在站台中心 |
  | 停站 | **10.0 s** | 开门 1.2 → 上下客保持 7.0 → 关门 1.2 → 待发 0.6（门叶沿车身滑动分离，可见开/关） |
  | 终点折返 | 12 s | 端点站开门→关门→折返换向，再反向运行 |

* **里程用真实值**：直接采用 OSM 轨道弧长换算，1 号线主线 **37.45 km**、支线 **2.57 km**（合计 40.02 km，
  与官方「全长 41 km」相差 2.4%），2 号线 **41.66 km**。**未做任何等比缩放**。
* **控制**：暂停/继续（全局）、复位（当前控制列车回到其线路起点）、1x/2x/4x 倍速（全局）、跟随列车（跟随当前控制列车）、
  线路/交路选择（作用于当前控制列车：1 号线主线、1 号线支线、2 号线）、清除目标、站点列表点选、站点悬浮窗派车、面板收起/展开。

### 点击优先级与交互规则

* **轻点列车**（距任一节车厢中心 30 px 内）→ 切为当前控制列车（面板/交路/HUD/跟随同步）；已是当前车则提示。
* **轻点站点** → 弹出站点悬浮窗（内容见下）。
* **轻点空白** → 收起展开的到站气泡，并关闭站点悬浮窗。

站点悬浮窗内容：

* **到达时间**：当前控制列车到达该站还需多久（游戏内时间；2x/4x 时括号里附实时时长），每 0.6 s 自动刷新；
* **到站路径**：「当前方向沿线直达」/「目标在当前方向后方：先到终点折返换向」/「需在四河站切换交路后到达」；
* **列车运行状态**：加速中/巡航/制动进站/开门中/折返换向中/已暂停 + 当前车速 + 当前位置（当前站 → 下一站）；
* **其他**：里程、可换乘线路、车站状态（在建/暂停运营）；**「列车运行到该站」按钮**（再点可取消目标）。

点击站点「列车运行到该站」后的实际派车规则：
1. 立即用**同一套状态机**在后台预演一遍到该站的完整行程（含各站停站与折返），算出预计到达与还需经过的站数；
2. 目标在当前方向前方且同一交路 → 正常逐站运行，到站后清除目标；
3. 目标在身后 → 继续驶向本方向终点站 → 折返换向 → 再驶向目标站；
4. 目标在 1 号线另一条交路上（支线站）→ 先运行到**四河**，在四河站停站时切换交路后抵达；四河已在身后时先折返；
5. 目标在**另一条线路**上（如列车在 1 号线、点了 2 号线的站）→ 悬浮窗提示「在 2 号线上，需先切换线路」，
   按钮变为「切换到 2 号线并运行到该站」，点击后列车转入新交路（若当前站不在新线路上，则从该交路起点站发车）并派车；
6. **在建站不能作为目标站**（按钮禁用并说明），列车驶过不停靠。

## 4. 触摸与视图交互（iPad 重点）

* 全部用 **Pointer Events**（`pointerdown/move/up/cancel` + `setPointerCapture`），并额外用 `click` 做一层兜底
  （时间戳去重，不影响拖拽/捏合）：即便某些 iOS Safari 环境下 pointer 事件缺失，点站点仍能命中。
* **轻点站点（tap）**：命中半径 30 px（直径 60 px ≥ 44 px 触控标准），**立即响应**，命中即弹悬浮窗；
  轻点空白处关闭悬浮窗。**区分点击与拖拽**：位移阈值 13 px，静止按压不论多久都算点击。
* **双指捏合缩放 + 单指拖动平移 + 双击缩放**（双击 1.9×，以双击点为锚点）；捏合以两指中点为锚点；
  缩放范围 `minZoom（适配全图）～ 16×`，平移限制在「线路范围 +6%」内。
* 视图变换作用于 SVG 的 `<g>`（`translate + scale`），`viewBox` 始终等于舞台像素尺寸，
  因此 SVG 用户单位 == CSS px，命中测试无需额外换算。
* **舞台尺寸永不脱同步**（修过的一个真 bug）：舞台大小会因面板内容、iOS 工具栏收起/展开等改变而**不一定触发 `resize`**；
  一旦 `viewBox` 落后于元素尺寸，SVG 会缩放内容，屏幕坐标与地图坐标就对不上、点站就会错位。
  现在用 **ResizeObserver 盯住舞台** + 监听 `visualViewport` 的 resize/scroll + `orientationchange`，
  `localPos()` 还按「舞台尺寸 ÷ 元素实际尺寸」做比例换算，`preserveAspectRatio="none"` 保证映射一致。
* `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no, viewport-fit=cover">`，
  舞台 `touch-action: none`，阻止双击缩放、橡皮筋滚动、长按选择/呼出菜单。
* **横竖屏都能用且不超出屏幕**：高度用 `100dvh`；竖屏时面板移到下方（最多 42dvh，内部滚动），
  横屏时面板宽 `clamp(240px, 28vw, 340px)`；舞台右上角「☰ 控制」一键收起/展开面板；
  舞台很矮时悬浮窗自动精简（隐藏次要行），保证「到达时间 + 状态 + 派车按钮」始终在屏内。

## 5. 声音：BGM + 开关门提示音 + 语音报站

面板里有一个 **🔇 声音关闭 / 🔊 声音开启** 按钮（默认关）。为什么默认关：iOS/Safari 要求音频必须由用户手势启动，
不点就放任何声音都会被浏览器拦。点一下开启后：

* **BGM**：循环播放“地铁运行”环境声（默认用 Web Audio **实时合成**：绍噪声 + 46/71 Hz 低频轰鸣，
  4 秒缓冲无缝循环、低通滤波、音量固定偏低）。想换成真实录音：把文件放进仓库（例如 `audio/bgm.mp3`），
  再把 `app.js` 里的 `var BGM_FILE = '';` 改成 `'audio/bgm.mp3'` 即可（留空则只用合成声，不会产生多余请求）。
  **为什么没直接下音频文件**：Wikimedia Commons 上唯一的 CC 许可地铁环境声都是 `.ogg/.flac`
  （如 TTC Subway Line 1 Ambience，CC BY 4.0），而 iOS Safari 对 Ogg Vorbis 支持不可靠，
  本机又没有 ffmpeg/任何编码器可以转成 mp3/m4a；加上应用要求零依赖/可离线，所以默认走合成，
  并留了 `audio/bgm.mp3` 这个口子给你换成真实录音。
* **开关门提示音**：Web Audio 合成的双音铃声——开门上行（G5→C6）、关门下行（C6→G5）、
  关门警报两声短促（B5-B5）；受音量倍数影响。
* **语音报站**：用浏览器自带的 `speechSynthesis`（`zh-CN`，自动选中文音色，无需任何外部资源），
  只在**当前控制的那列车**上播报，文案：
  * 到站开门：「〔站名〕站到了，请下车，注意列车与站台之间的空隙」

### 更新与版本戳（给 iPad 主屏 web app 用）

iPad 把它「添加到主屏」后是 standalone 窗口：**没有地址栏、没有刷新按钮**；而 GitHub Pages 给 HTML/JS 配了
`cache-control: max-age=600`，所以关掉重开也可能还是旧版。为此提供两样东西：

1. **可见版本戳**：页面加载时用 `fetch('version.json', { cache: 'no-store' })` 现取版本，
   显示在两处——舞台右上角小徽标（如 `v2026-09-12.2210`）与控制面板「列车控制」卡片里的版本行
   （如 `v2026-09-12.2210 · 5f66230`）。旧版页面看徽标就能一眼分辨。
2. **「⟳ 刷新」按钮（舞台左上角、HUD 左边、始终可见）**：不看版本、直接**强制整页重拉** ——
   带 `_v=<时间戳>` 的地址 + `location.replace()`，同时因为资源是**按版本号加载**的
   （`index.html` 里的内联 bootstrap 先 `fetch('version.json?_v=…', {cache:'no-store'})` 拿版本，
   再注入 `./style.css?v=<版本>`、`./data.js?v=<版本>`、`./app.js?v=<版本>`）——
   所以 GitHub Pages 的 `max-age=600` 缓存拦不住，点一下一定能拿到新代码。
   （静态的 `<link rel=stylesheet>` 保留着，先渲染不闪；版本号加载的那份后到生效。）
3. **「⟳ 检查更新」按钮**（右侧面板「列车控制」里）+ **右上角版本徽标**；
   逻辑：拉一次 `version.json?_v=<时间戳>`（`cache:'no-store'`）与服务端版本比对——
   * 版本不同 → **带 `_v=` 的 cache-busting 地址 + `location.replace()` 强制重载**；
   * 版本相同 → 提示「已是最新（再点一下强制刷新）」，**4 秒内再点一次**则忽略比对、直接强制重载；
   * 拉不到版本（离线 / `file://`）→ 只提示失败，**绝不自动重载**（否则会无限刷新）。

刷新 URL 由 `refreshUrlFor(href, stamp)` 构造：**保留原有查询参数（如 `?selftest=1`）与 hash，仅覆盖 `_v`**，
并使用当前 `pathname`（在 Pages 子路径 `/chengdu-metro-line1/` 下也正确）。

**发版流程**（让版本戳与资源 URL 都更新）：改代码 → `git commit` → `./tools/bump-version.sh` →
`git add version.json && git commit` → `git push`。改 `bump-version.sh` 里的 `commit` 取“生成时刻的 HEAD”，
也就是上一步的代码提交；**版本号变了，`?v=` 就会变，iPad 上点「⟳ 刷新」即必定拿到新代码**。

10. **`file://` 直接打开时读不到 `version.json`**（fetch 被同源策略拦），版本徽标会显示「v未知 · 无法读取 version.json」；

## 9. 开发与验证工具链

应用本身是**零依赖零构建**的静态页面；下面这些只是**开发期工具**，运行时不需要。
