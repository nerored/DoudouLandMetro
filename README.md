# 豆豆国的地铁 — 成都地铁全网（1~30 号线 + S3 资阳线）+ 有轨电车蓉2号线 SVG 线路图 + 列车运行模拟

纯 vanilla 单页网页应用：用 SVG 绘制**成都地铁全网 17 条线路 + 有轨电车蓉2号线（共 18 条线路）**
（按 OpenStreetMap 真实轨道几何与站点坐标，398 个去重站点 / 85 个换乘站），
站点轻点即弹出悬浮窗（到达时间 / 列车状态 / 派车按钮），
**每条线路一列列车**（共 18 列；地铁 8 车厢、有轨电车 5 节短车）沿线按站运行：
区间加速—巡航—制动进站—到站停车—开关门—发车—终点折返（7 号线环线绕圈、方向标内环/外环），
支持 iPad 双指缩放/单指平移/双击缩放。

* **零外部依赖、零构建步骤**：没有 CDN、没有 web font、没有图标字体、没有 npm 包、没有模块打包。
  只有 5 个文件 + 内联/内嵌 SVG，直接 `file://` 打开或任意静态服务器托管都能跑。
  （`tools/build-data.py` 是**一次性数据生成脚本**，跑网页不需要它。）
* 目标设备：**iPad（触摸优先）**，同时兼容鼠标（滚轮缩放 + 拖动平移）。

启动方式（二选一）：

```bash

./serve.sh 8080            # 等价于 python3 -m http.server 8080 --bind 0.0.0.0

# B. 直接打开
#   在本机浏览器打开 index.html（file:// 也能正常运行：脚本全部是普通 <script>，无模块/无 fetch）
```

### 在 iPad 上打开（本机是 WSL2）

`serve.sh` 会自动打印候选地址，步骤：

1. 在 WSL 里运行 `./serve.sh 8080`（已 `--bind 0.0.0.0`）。
2. 在 **Windows 管理员 PowerShell** 里把端口转发到 WSL（只需做一次；`<WSL_IP>` 用 `hostname -I` 查看，
   一般形如 `172.2x.x.x`）：

   ```powershell
   netsh interface portproxy add v4tov4 listenport=8080 listenaddress=0.0.0.0 `
     connectport=8080 connectaddress=<WSL_IP>
   netsh advfirewall firewall add rule name="potato-8080" dir=in action=allow protocol=TCP localport=8080
   ```

3. iPad 与电脑连同一 Wi-Fi，Safari 打开 `http://<Windows 局域网 IP>:8080/index.html`
   （Windows 上用 `ipconfig` 找 IPv4 地址，通常 `192.168.x.x`）。

注意事项：WSL2 的 IP 每次重启可能变化，变化后要
`netsh interface portproxy delete v4tov4 listenport=8080 listenaddress=0.0.0.0` 再重加；
若 portproxy 不通，可直接访问 `http://<WSL_IP>:8080/`（需 Windows 防火墙放行），
或把目录复制到 Windows 侧用 `python -m http.server 8080` 起服务。

## 3. 列车（每线一列，共 18 列：地铁 8 车厢 / 有轨电车 5 节短车）与运行模拟

* **列车数量**：每条线路 1 列（18 条线路 → **18 列**），**打开网页即全部自动运行**
  （各自从始发站发车、区间加速、到站开门关门、终点折返；7 号线环线绕圈不折返）。
* **编组两套几何**（同一套弧长参数化管线，只是参数不同；`CFG` / `CFG.tram`）：
  * **地铁**：8 车厢，车长 13、间隙 1.3、半宽 3.0（整列 113.1 地图单位；为可视性做了夸张，真车 20 m × 3 m）。
  * **有轨电车**：**5 节短车**，车长 8.6、间隙 0.9、半宽 2.6（整列 46.6 单位，约地铁的 41%）——
    对应蓉2号线的阿尔斯通 Citadis 302 低地板 5 车编组（车长约 32.6 m）。
  * 端口站外的折返段长 120 单位，两种编组都放得下（有自检断言）。
* **车体画法**（两个品类共用）：车体由**路径弧长参数化**生成：以列车前端里程出发按 `fS = sHead − dir·i·(车长+间隙)`、
  `rS = fS − dir·车长` 求每节车厢首尾，再沿线路采样点用法向偏移曲线生成车身轮廓——
  因此转弯时整列车像蛇一样贴着线路弯曲，车头朝该点切线方向。每节车厢：连续**侧窗带**（不是一个个小方窗）、
  **两对双开门**（门叶叠在窗带上把它打断，开门时向两侧滑开）、车顶线条与空调机组、车厢之间的风挡缝；
  车头是圆润收窄的**鼻锥 + 深色驾驶室端面 + 挡风玻璃 + 两颗前照灯**，车尾是圆钝收尾 + **红色尾灯**，两端一眼可辨。
* **品类涂装区分**：地铁 = **白车身 + 线路色腰线**（车顶中央色带）；
  有轨电车 = **车身直接用线路色铺满 + 浅色窗带**（苹果绿车、白窗），所以在图上一眼能分出电车与地铁（`.train.tram`）。
  两者的车身颜色都取所属线路的 `color`（线路色只表示线路）。
* **列车强调显示**（便于在图上找到车）：车身外一圈**白色光晕 + 线路色描边**（带缓慢呼吸动画，深浅底图上都醒目）；
  车头上方有一个**跟随标签贴片**（线路徽标 + 实时状态，如「1号线｜巡航 60km/h」「2号线｜开门中」），
  贴片可点（等同点列车切换控制对象）；当前控制的车额外有**加粗描边 + 车头虚线选中环**。
* **点击列车切换控制对象**：轻点地图上的列车，或面板顶部「列车」卡片（每列车一张，显示当前位置与状态），
  即可把“当前控制列车”换成它 —— 右侧面板的**线路/交路**、HUD、导航目标、跟随视图、暂停/复位均随之更新。
  当前控制的车有加粗描边与车头虚线选中环，另一列不隐藏、照常运行（只是提示不弹、只静默发车）。
* **下一站强调 + 到站气泡**：每列车前方**下一站在地图上有脉冲圆圈**（按所属线路配色）；站名上方悬浮
  **到站气泡**显示「线路徽标 + 还差 X 分 Y 秒」；若同一站同时是多列车的下一站，气泡**折叠为一条**
  「N 趟列车 · 最短时间」，点它展开成多条单独气泡（每条可点，点了就切到那列车）；
  **点地图空白处收起展开的气泡**。气泡会自动避开 HUD、自动重叠避让，并始终留在舞台内。
* **18 节车厢刚性连结与开门动画**：每节车厢的门叶沿车身法向滑开（开/关 1.2 s，停站共 10 s），
  当前控制的车有加粗描边 + 车头虚线环；点列车/列车卡切换控制对象，其余列车静默运行。
* **动力学**（真实时间戳驱动：`requestAnimationFrame` + `performance.now()` 求 delta；单帧 delta 上限 0.12 s，
  大 delta 再拆成 ≤ 0.04 s 子步，切后台回来不跳变；多列车在同一循环里各自子步推进）：

  | 项 | 取值 | 说明 |
  |---|---|---|
  | 巡航速度 | 60 km/h | 线路设计最高 80 km/h；区间巡航取 60 |
  | 加速度 | 0.75 m/s² | 加速到巡航约 185 m |
  | 制动减速度 | 0.9 m/s² | 按 `v = √(2a·remain)` 收敛到 0，停在站台中心 |
  | 停站 | **10.0 s** | 开门 1.2 → 上下客保持 7.0 → 关门 1.2 → 待发 0.6（门叶沿车身滑动分离，可见开/关） |
  | 终点折返 | 12 s | 端点站开门→关门→折返换向，再反向运行 |

* **里程用真实值**：直接采用 OSM 轨道弧长换算（全网 18 条线路逐条给出，见第 2 节的表格），**未做任何等比缩放**。
* **控制**：暂停/继续（全局）、复位（当前控制列车回到其线路起点）、**1x / 2x / 5x / 10x 倍速**（全局）、
  跟随列车（跟随当前控制列车）、线路/交路选择（作用于当前控制列车；18 条线路共 20 个交路，按线路分组的下拉）、
  清除目标、站点列表点选、站点悬浮窗派车、面板收起/展开。

### 控制区：右侧 dock ↔ 底部抽屉（同一套内容）

17 条地铁线路 + 1 条有轨电车 + 398 站以后，「一条长列表到底」的面板已经不好用了（要滚很久才找到列车/站点）。
现改成**四个 tab + 一个滚动区**（设计契约见 `DESIGN.md` §4）：

| Tab | 内容 |
|---|---|
| **线路** | 18 个线路色块（点一下只看该线，可多选）+ 全网统计。**宽屏（iPad/PC）下是三列网格**竖向铺开，手机上是横滑带；非地铁线路（有轨电车/市域铁路）的色块上直接写品类名 |
| **列车** | 当前列车卡（速度/里程/目标站/ETA）+ **切换列车列表**（宽屏是竖向 1 列、约 5 行可见，手机上是横滑带）+ 交路选择 + 控制 |
| **导航** | 目标站 / 预计到达 / 还需经过 + 清除目标 |
| **站点** | **搜索框（中英文都行）** + 按线路折叠的站表（只展开当前线路） |
| **图例** | 站点符号说明（换乘 / 普通 / 端点 / 在建·暂停）+ **版本与更新**（版本戳 + 检查更新）+ 数据来源与 ODbL 版权 |

* **宽屏横屏（≥760px 且横屏）**：面板是右侧 dock（300~360px）；它现在是**浮层**——收起时地图真的变宽。
  收起/展开：**面板左缘的竖向把手**（拖动跟手：往右推收起、往左拉展开；点一下也切换）——
  收起后把手仍留在屏幕右缘，随时可以再拉出来。顶部不再有「控制」按钮。
* **手机 / 竖屏**：面板变成**底部抽屉**，把手三档（把手上还有当前列车胶囊）：
  收起 = 把手 + tab + 胶囊（111px，地图占大头）/ 半开 = 52dvh（默认，正好能装下整条线网）/ 全开 = 86dvh；
  拖动把手吸附到最近档位，点一下循环三档。
* **唯一滚动区**：抽屉/面板主体（`.panel-body`）——页面与地图**从来不滚**，
  所以不会出现“iPhone 上地址栏一缩、地图就跑位”那类问题。宽屏下的「切换列车」是块内嵌的竖向列表
  （最多 5 行高，其余在列表内滑，滑到头会接着滚面板）。
* **小屏降噪**：舞台宽度 < 480px 时，列车贴片与到站气泡只保留当前控制列车那一个（强调圈照画）。
* **站名标签按屏幕分档**：宽舞台（平板/桌面）15px、窄舞台（手机）11px——都是屏幕恒定字号，
  手机用小字号才能塞下足够多的站名（用户反馈“缩小了也不显示”）；同优先级的标签用**空间哈希**打散，
  避免预算全部花在最北边那一撮上、缩小时只剩西北角几个站名。
* **双击站点行 = 视角聚焦**：单击仍是“列车运行到该站”，**双击**会把地图居中到该站并放大到看得清的档位
  （跟随列车开着时会先关掉，否则下一帧就被拉回去）。
* **图标全部是内联 SVG**（无图标字体/CDN）；每个可点元素都有 hover / active / focus-visible 三态。

### 点击优先级与交互规则

* **轻点列车**（距任一节车厢中心 30 px 内）→ 切为当前控制列车（面板/交路/HUD/跟随同步）；已是当前车则提示。
* **轻点站点** → 弹出站点悬浮窗（内容见下）。
* **轻点空白** → 收起展开的到站气泡，并关闭站点悬浮窗。
* **站点优先于列车**：列车每站要停 10 s，停站时车身正好压住站台；若让列车优先，那 10 秒里点站会“没反应”。
  所以两处命中同时成立时按“离站点圆心更近”判给站点；列车仍可在区间、车头标签或右侧面板「列车」卡片上点中。

站点悬浮窗内容：

* **到达时间**：当前控制列车到达该站还需多久（游戏内时间；倍速≠1 时括号里附实时时长），每 0.6 s 自动刷新；
* **到站路径**：「当前方向沿线直达」/「目标在当前方向后方：先到终点折返换向」/「需在四河站切换交路后到达」；
* **列车运行状态**：加速中/巡航/制动进站/开门中/折返换向中/已暂停 + 当前车速 + 当前位置（当前站 → 下一站）；
* **其他**：里程、可换乘线路、车站状态（在建/暂停运营）；**「列车运行到该站」按钮**（再点可取消目标）。

点击站点「列车运行到该站」后的实际派车规则：
1. 立即用**同一套状态机**在后台预演一遍到该站的完整行程（含各站停站与折返），算出预计到达与还需经过的站数；
2. 目标在当前方向前方且同一交路 → 正常逐站运行，到站后清除目标；
3. 目标在身后 → 继续驶向本方向终点站 → 折返换向 → 再驶向目标站；
4. 目标在 1 号线另一条交路上（支线站）→ 先运行到**四河**，在四河站停站时切换交路后抵达；四河已在身后时先折返；
5. 目标在**另一条线路**上（如列车在 1 号线、点了 2 号线的站）→ 悬浮窗提示「在 2 号线上，需先切换线路」，
   按钮变为「切换到 2 号线并运行到该站」，点击后列车转入新交路（若当前站不在新线路上，则从该交路起点站发车）并派车；
6. **在建站不能作为目标站**（按钮禁用并说明），列车驶过不停靠。

## 4. 触摸与视图交互（iPad 重点）

* 全部用 **Pointer Events**（`pointerdown/move/up/cancel` + `setPointerCapture`），并额外用 `click` 做一层兜底
  （时间戳去重，不影响拖拽/捏合）：即便某些 iOS Safari 环境下 pointer 事件缺失，点站点仍能命中。
* **轻点站点（tap）**：命中半径 30 px（直径 60 px ≥ 44 px 触控标准），**立即响应**，命中即弹悬浮窗；
  轻点空白处关闭悬浮窗。**区分点击与拖拽**：位移阈值 13 px，静止按压不论多久都算点击。
* **双指捏合缩放 + 单指拖动平移 + 双击缩放**（双击 1.9×，以双击点为锚点）；捏合以两指中点为锚点；
  缩放范围 `minZoom（适配全图）～ 16×`，平移限制在「线路范围 +6%」内。
* 视图变换作用于 SVG 的 `<g>`（`translate + scale`），`viewBox` 始终等于舞台像素尺寸，
  因此 SVG 用户单位 == CSS px，命中测试无需额外换算。
* **舞台尺寸永不脱同步**（修过的一个真 bug）：舞台大小会因面板内容、iOS 工具栏收起/展开等改变而**不一定触发 `resize`**；
  一旦 `viewBox` 落后于元素尺寸，SVG 会缩放内容，屏幕坐标与地图坐标就对不上、点站就会错位。
  现在用 **ResizeObserver 盯住舞台** + 监听 `visualViewport` 的 resize/scroll + `orientationchange`，
  `localPos()` 还按「舞台尺寸 ÷ 元素实际尺寸」做比例换算，`preserveAspectRatio="none"` 保证映射一致。
* `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no, viewport-fit=cover">`，
  舞台 `touch-action: none`，阻止双击缩放、橡皮筋滚动、长按选择/呼出菜单。
* **横竖屏都能用且不超出屏幕**：高度用 `100dvh`；竖屏时面板移到下方（最多 42dvh，内部滚动），
  横屏时面板宽 `clamp(300px, 26vw, 360px)`；舞台右上角「控制」一键收起/展开面板（收起后地图满宽）；
  舞台很矮时悬浮窗自动精简（隐藏次要行），保证「到达时间 + 状态 + 派车按钮」始终在屏内。

## 5. 声音：BGM + 开关门提示音 + 语音报站

**左上角 HUD 的品牌行里**有一个 **声音开关**（内联 SVG 喇叭图标 + 「声音开/关」文案，默认关），
与「刷新」并排。为什么默认关：iOS/Safari 要求音频必须由用户手势启动，
不点就放任何声音都会被浏览器拦。点一下开启后：

* **BGM**：循环播放“地铁运行”环境声（默认用 Web Audio **实时合成**：绍噪声 + 46/71 Hz 低频轰鸣，
  4 秒缓冲无缝循环、低通滤波、音量固定偏低）。想换成真实录音：把文件放进仓库（例如 `audio/bgm.mp3`），
  再把 `app.js` 里的 `var BGM_FILE = '';` 改成 `'audio/bgm.mp3'` 即可（留空则只用合成声，不会产生多余请求）。
  **为什么没直接下音频文件**：Wikimedia Commons 上唯一的 CC 许可地铁环境声都是 `.ogg/.flac`
  （如 TTC Subway Line 1 Ambience，CC BY 4.0），而 iOS Safari 对 Ogg Vorbis 支持不可靠，
  本机又没有 ffmpeg/任何编码器可以转成 mp3/m4a；加上应用要求零依赖/可离线，所以默认走合成，
  并留了 `audio/bgm.mp3` 这个口子给你换成真实录音。
* **开关门提示音**：Web Audio 合成的双音铃声——开门上行（G5→C6）、关门下行（C6→G5）、
  关门警报两声短促（B5-B5）；受音量倍数影响。
* **语音报站**：用浏览器自带的 `speechSynthesis`（`zh-CN`，自动选中文音色，无需任何外部资源），
  只在**当前控制的那列车**上播报，文案：
  * 到站开门：「〔站名〕站到了，请下车，注意列车与站台之间的空隙」
  * 关门警报：「车门即将关闭，请勿靠近车门」
  * 发车：「欢迎乘坐**豆豆国地铁X号线**，下一站 〔站名〕」；7 号线环线再多一个方向词：
    「欢迎乘坐豆豆国地铁7号线**外环/内环**列车，下一站 〔站名〕」（内环 = 顺时针、外环 = 逆时针）
  高倍速下只报站名（否则语速赶不上 10 秒停站）。切后台时 BGM 自动暂停，回来自动继续。

### 更新与版本戳（给 iPad 主屏 web app 用）

iPad 把它「添加到主屏」后是 standalone 窗口：**没有地址栏、没有刷新按钮**；而 GitHub Pages 给 HTML/JS 配了
`cache-control: max-age=600`，所以关掉重开也可能还是旧版。为此提供两样东西：

1. **可见版本戳**：页面加载时用 `fetch('version.json', { cache: 'no-store' })` 现取版本，
   显示在**左下角图例的最后一行**（如 `v2026-09-13.0136 · a060776`，点一下=检查更新）。旧版页面看这一行就能一眼分辨。
2. **「⟳ 刷新」按钮（舞台左上角、HUD 左边、始终可见）**：不看版本、直接**强制整页重拉** ——
   带 `_v=<时间戳>` 的地址 + `location.replace()`，同时因为资源是**按版本号加载**的
   （`index.html` 里的内联 bootstrap 先 `fetch('version.json?_v=…', {cache:'no-store'})` 拿版本，
   再注入 `./style.css?v=<版本>`、`./data.js?v=<版本>`、`./app.js?v=<版本>`）——
   所以 GitHub Pages 的 `max-age=600` 缓存拦不住，点一下一定能拿到新代码。
   （静态的 `<link rel=stylesheet>` 保留着，先渲染不闪；版本号加载的那份后到生效。）
3. **「检查更新」按钮**（右侧面板 列车 tab 的「控制」卡片里 + 左下角图例的版本行）；
   逻辑：拉一次 `version.json?_v=<时间戳>`（`cache:'no-store'`）与服务端版本比对——
   * 版本不同 → **带 `_v=` 的 cache-busting 地址 + `location.replace()` 强制重载**；
   * 版本相同 → 提示「已是最新（再点一下强制刷新）」，**4 秒内再点一次**则忽略比对、直接强制重载；
   * 拉不到版本（离线 / `file://`）→ 只提示失败，**绝不自动重载**（否则会无限刷新）。

刷新 URL 由 `refreshUrlFor(href, stamp)` 构造：**保留原有查询参数（如 `?selftest=1`）与 hash，仅覆盖 `_v`**，
并使用当前 `pathname`（在 Pages 子路径 `/DoudouLandMetro/` 下也正确）。

**发版流程**（让版本戳与资源 URL 都更新）：改代码 → `git commit` → `./tools/bump-version.sh` →
`git add version.json && git commit` → `git push`。改 `bump-version.sh` 里的 `commit` 取“生成时刻的 HEAD”，
也就是上一步的代码提交；**版本号变了，`?v=` 就会变，iPad 上点「⟳ 刷新」即必定拿到新代码**。


* **为什么底图要单独两步**：底图坐标必须和轨道落在同一套「等距圆柱投影 + 平移」里，而平移量取决于**全部轨道**
  的包围盒；所以先用 `--write-shift` 把平移量写到 `tools/basemap-shift.json`（生成物，已 gitignore），再生成底图。
* **底图抽稀策略**（`tools/build-basemap.py`）：水系只保留**有名字**的，河流/渠道 12 m、湖泊轮廓 8 m 容差；
  道路分两档——距任一轨道 < 3 km 用 motorway/trunk/primary（34 m 容差），更远只留 motorway/trunk（60 m 容差），
  并裁掉轨道包围盒之外 6 km 以外的要素（平移范围受约束，那些数据永远画不到）。

  **8 / 13 / 30 号线**官方图上图例色与描边色不一致，取的是图例值（`colorVerified:false`）——**待核实**。
* **10 号线的范围**：OSM 上只有 `新平 ↔ 武侯祠` 一条全线关系（18 站 / 40.53 km）；三期北延（人民公园/骡马市方向）
  OSM 还没有关系，**未收录**。另一条子段关系（`武侯祠 ↔ 花桥`）里有 **高升桥** 站而选用关系里没有，

## 8. 已知问题 / 未实现项

1. **一条线路一列车，没有时刻表、没有多车追踪、没有区间闭塞**：全网 18 条线路共 18 列同时运行，
   而真实城市里 1 号线高峰就有 62 列上线。
2. **地铁 8 车厢是任务要求**（真实 1 号线为 6 节编组 B 型车、19 号线是 4 节市域 A 型车）；
   **有轨电车按真实编组 5 节短车**（蓉2号线 Citadis 302，车长约 32.6 m），但它与地铁共用同一套几何参数化，
   只是在 `CFG.tram` 里换了参数。真实涂装是蓝绿/浅蓝/明黄三种（由成都地铁运营），
   本应用为了「线路色只表示线路」统一用线路色铺满车身——**涂装为示意，不是实车配色**。
   车长与站台长度都做了夸张（按地图比例尺，真实 8 节车只有几个地图单位，肉眼不可见）。
3. 底图的**街区纹理、网格**是装饰；水系/湖泊/快速路来自 OSM 但同样**只作示意，不能用于导航**。
4. **线路色**：1~7 号线为官网线网图取样 / 维基 `Module:Adjacent stations`；**8 / 13 / 30 号线在官方图上
   图例色与描边色不一致，取的是图例值**（`colorVerified:false`）——待核实。
5. **2 号线东段「暂停运营」6 站与在建的龙泉驿火车站**：本模拟按全线运行、在建站不停靠，
   未模拟真实的分段运营与改建施工。
6. **车站形式**只有 1 号线收录（百科给了表格）；2 号线未收录，新上线的 15 条线同样未收录。
7. 未做无障碍朗读（只有画布级 `aria-label`）与深色模式。
8. **换乘关系**：1/2 号线是逐条与百科词条核对过的；**其余 15 条线的换乘站是按 OSM 关系里的同名站
   自动合并推导**，没有逐条核对（同名不同站、出闸换乘之类会有出入）；`tr` 字段里的「在建换乘」
   也只覆盖 1/2 号线的百科内容。
9. **10 号线的范围**：OSM 上只有 `新平 ↔ 武侯祠`（18 站 / 40.53 km）；三期北延（人民公园/骡马市方向）
   OSM 还没有关系，**未收录**。另一条子段关系（`武侯祠 ↔ 花桥`）里有**高升桥**站而选用的全线关系里没有，
   所以图上 10 号线缺这一站——**待核实**。
10. **18 / 19 号线共线段**（天府站 → 天府机场北）两条关系各画一遍，图上会看到两色并行；
    未做“共线合并显示”。
11. **7 号线环线只跑一个方向**：真实运营分内环/外环两条交路，本模拟每线只有一列车，沿固定的
    外环（逆时针）方向绕圈；方向文案已按官方口径标注内环/外环。
12. 未在真机 iPad 上跑过（无设备）。
13. **`file://` 直接打开时读不到 `version.json`**（fetch 被同源策略拦），版本戳会显示「v未知 · 无法读取 version.json」；
   这是预期行为——用 http(s) 部署（GitHub Pages / `./serve.sh`）就能正常显示。刷新按钮在两种情况都能用。
14. **声音**：BGM 是现场合成的环境声（不是真实录音），想要真实录音就把 `audio/bgm.mp3` 放进仓库；
   语音报站依赖系统 TTS（iOS 的「设置 → 辅助功能 → 朗读内容」里需已安装中文语音，一般是自带的婷婷）；
   是否播报、音色、语速最终由浏览器/系统决定，无声音时优先检查左上角 HUD 里的**声音开关**是否已开与 iPad 侧音量。
